Patterns across module reflections

Pattern 1: It ran, but can it be trusted?

In each module I came back to the same problem through different material: code, a model, a statistic, and an agent.

In this work I learned why running successfully is not the same as working responsibly. Code can run without an error, tests can appear green, and an AI system can remain operational while still producing unsafe or misleading results. The output is only the starting point. Someone still has to judge whether it can be trusted.

Module 1, Launch into Computing. Read the Module 1 learning outcomes and the case behind them: A1: Code Exploration.

I also learned why the smallest defensible model can be the stronger business solution. Both models achieved 96.5 percent accuracy, but Random Forest produced one additional false negative and offered no improvement that justified its added complexity.

Module 2, Understanding Artificial Intelligence. Read the Module 2 learning outcomes and the study behind them: Instantiating the Smallest Defensible Model.

The central change in this module was my move from producing numerical output to judging whether that output deserved to be trusted.

Module 3, Numerical Analysis. Read the reflection: From Output to Judgment.

An agent can follow its instructions correctly and still produce an unfair result.

Module 4, Intelligent Agents. Read Collaborative Learning Discussion 1.

Pattern 2: Who answers for it?

The second pattern is accountability: who answers when a system appears to work but causes harm?

From the Horizon, Amazon, COMPAS, Air Canada, and PowerSchool cases I learned that ethical principles mean little without enforceable accountability. In each case I saw the consequences of trusting an apparently credible system without enough professional scrutiny or operational preparation.

Module 1, Launch into Computing. Read the Module 1 learning outcomes.

In Module 2 I learned why human oversight must involve meaningful understanding. Making a clinician answer for a decision they cannot follow does not create genuine accountability. It creates a moral crumple zone.

Module 2, Understanding Artificial Intelligence. Read the Module 2 learning outcomes and the discussion behind them: Collaborative Learning Discussion 2.

The key question is therefore not only whether an agent can act independently. We also need to ask who defines its objective and who bears the consequences of its actions.

Module 4, Intelligent Agents. Read the initial post.

Pattern 3: AI as a pointer, not as evidence

AI now helps point me toward what may be worth checking, but I do not treat its output as evidence. It only becomes useful when I return to the original source and verify it myself.

Module 3, Numerical Analysis. Read the reflection and the correction it describes: Brown Table II: the figure and the discussion. My earlier declaration of AI use appears in Appendix C of the Module 2 report.

Application to professional or project work

In two parts of this portfolio I record how I have already taken the learning beyond the coursework and into my teaching practice.

I have used my R primer with my own students. Introducing R at the high school level gives them an early opportunity to work with large datasets, turn the data into charts, and explain what the results show.

In the classroom, from the Module 3 reflection: Read From Output to Judgment.

I also apply the learning to how I approach my own work. I design AI-supported tools and workflows that reduce routine teacher workload without handing professional judgement over to the technology.
