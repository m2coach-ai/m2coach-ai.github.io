1. Know the three RStudio areas

AreaPurposeWhat you should expect
Script Editor (upper-left)Write and save your assignment code.Code stays here until you highlight it and press Ctrl + Enter.
Console (lower-left)R runs code here and displays results, warnings, and errors.A blue > prompt means R is ready.
Environment (upper-right)Stores objects you create.Objects such as covid and state_frequency should appear here after successful creation.
Key rule: A line containing <- usually creates or changes an object. No printed Console output is often normal. Look in the Environment.

2. Beginning setup and diagnostic

Assignment identification

  • Section: Basic data visualization
  • Current step: Prepare and verify the supplied CSV before plotting
  • Prerequisites: RStudio open; the CSV saved in a known folder; a new R script open

2.1 Put the file in a simple folder

  1. Create a folder you can find, for example Documents/R/COVID_Plotting.
  2. Place Covid19 India (Jan 20 Mar 20).csv in that folder.
  3. In RStudio choose File > New File > R Script.
  4. Save the script in the same folder as COVID_Plotting_Assignment.R.
  5. Choose Session > Set Working Directory > To Source File Location.
Common miss: Saving the script does not automatically import the CSV. Setting the working directory only tells R where to look.

2.2 Verify that R sees the file

PASTE under a heading in the Script Editor:

# STEP 1: Check that R can see the supplied CSV file
list.files()

HIGHLIGHT only list.files(), then press Ctrl + Enter.

  • Console output expected: Yes. The filename should be listed.
  • New Environment object expected: No.
Checkpoint 1: Continue only if the Console lists Covid19 India (Jan 20 Mar 20).csv. The spelling, spaces, and parentheses matter.
What every symbol means
  • # starts a comment. R does not run the words after it.
  • list.files is the function name. It asks R to list files in the working directory.
  • () means “run this function.” The parentheses are empty because no extra instruction is needed.

3. Import and inspect the dataset

3.1 Create the data-frame object

# STEP 2: Import the COVID-19 CSV as a data frame
covid <- read.csv("Covid19 India (Jan 20 Mar 20).csv")

HIGHLIGHT the complete line beginning covid <-. Press Ctrl + Enter.

  • Console output expected: No printed table is expected.
  • New Environment object expected: Yes, covid should appear with 270 observations and 7 variables.
Do not type only covid before running the creation line. That causes Error: object 'covid' not found.
Code explained
  • covid is the object name we chose.
  • <- means “store the result on the right inside the object on the left.”
  • read.csv reads a comma-separated data file.
  • Quotation marks tell R that the filename is text, not an object name.

3.2 Inspect structure, names, and missing values

# STEP 3: Inspect the imported dataset
str(covid)
names(covid)
colSums(is.na(covid))

Run one complete line at a time with Ctrl + Enter.

  • str(covid): output expected; no new object.
  • names(covid): output expected; no new object.
  • colSums(is.na(covid)): output expected; no new object.
Expected checks: 270 rows, 7 columns, and zero missing values in every column. Because read.csv() makes names safe for R, State/UnionTerritory becomes State.UnionTerritory. The other required names remain ConfirmedIndianNational, ConfirmedForeignNational, Cured, and Date.
New symbols explained
  • is.na(covid) checks each cell and marks whether it is missing.
  • colSums(...) adds the missing-value marks separately for each column.
  • The inner parentheses run first. R checks for missing values, then totals them.
Checkpoint 2: Continue only if covid exists and the column names match. If they do not, do not guess. Recheck the filename and import.

4. Task 1: Bar chart of report frequency

What the bars mean: the number of dataset rows, or reports, recorded under each state/union territory label. This is not the number of people.

4.1 Create the frequency table first

# TASK 1: Count the number of reports for each state or union territory
state_frequency <- table(covid$State.UnionTerritory)

Highlight and run the complete line.

  • Printed output expected: No.
  • Environment object expected: Yes, state_frequency.

Now display it:

state_frequency

Highlight that line and run it. Printed output is expected. No new object is created.

Code explained
  • table() counts how often each distinct label occurs.
  • $ means “select this column from this data frame.”
  • covid$State.UnionTerritory means the state/territory column inside covid.

4.2 Verify the count before plotting

# Check that all report frequencies add back to the 270 dataset rows
sum(state_frequency)
length(state_frequency)
sort(state_frequency, decreasing = TRUE)

Run one line at a time. Expected results: total 270, 27 distinct labels, and Kerala as the largest frequency with 52 reports.

Data-quality observation: Some places use more than one label, such as Ladakh and Union Territory of Ladakh. There are also spelling variants such as Chattisgarh/Chhattisgarh and Pondicherry/Puducherry. For this beginner activity, the chart preserves the supplied labels. Mention this limitation rather than silently changing the data.

4.3 Draw the bar chart

# Draw a horizontal bar chart so long place names remain readable
barplot(sort(state_frequency),
        horiz = TRUE,
        las = 1,
        cex.names = 0.65,
        col = "steelblue",
        main = "Frequency of COVID-19 Reports by State/Union Territory",
        xlab = "Number of reports")

HIGHLIGHT the entire command from barplot( through the final ). Press Ctrl + Enter.

  • Output expected: Yes, in the Plots pane.
  • Environment object expected: No.
Interpretation: Kerala has the greatest number of reports because it appears across the longest portion of this dataset. A taller bar does not necessarily mean more individual cases.
Checkpoint 3: Confirm that the chart has horizontal bars, readable place names, and Kerala at 52.

5. Task 2: Pie chart of case-severity levels

Important assignment ambiguity: The file contains Indian and foreign confirmed counts, but it does not contain a variable named “severity.” This guide makes the method explicit: total confirmed cases per report are calculated, then grouped as Low = 0–5, Moderate = 6–20, and High = 21+. These are learning categories, not medical severity classifications.

5.1 Create total confirmed cases for each report

# TASK 2: Add Indian and foreign confirmed cases for each report
covid$TotalConfirmed <- covid$ConfirmedIndianNational +
                        covid$ConfirmedForeignNational

Highlight both lines together and run them.

  • Printed output expected: No.
  • Environment change expected: Yes. covid should now have 8 variables.
Code explained
  • covid$TotalConfirmed names a new column inside covid.
  • + adds the two values on each row.
  • The line break after + is allowed because R can see the calculation is unfinished.

5.2 Create and count the categories

# Group each report into a transparent learning category
covid$SeverityLevel <- cut(
  covid$TotalConfirmed,
  breaks = c(-Inf, 5, 20, Inf),
  labels = c("Low (0-5)", "Moderate (6-20)", "High (21+)"),
  right = TRUE
)

# Create the frequency table before trying to display it
severity_frequency <- table(covid$SeverityLevel)
severity_frequency

First highlight the whole cut(...) command and run it. Then run the creation line for severity_frequency. Only after that, run the display line.

  • After cut(...): no printed output; covid should have 9 variables.
  • After severity_frequency <- ...: no output; a new Environment object should appear.
  • After severity_frequency: output expected.
Expected counts: Low = 177, Moderate = 75, High = 18. They must total 270.
Symbols and arguments explained
  • cut() divides numerical values into groups.
  • breaks = supplies the category boundaries.
  • c() combines several values into one ordered set.
  • -Inf and Inf mean negative infinity and positive infinity, ensuring all values fit.
  • Commas separate the instructions given to a function.
  • right = TRUE means the upper boundary belongs to the category. Therefore 5 is Low and 20 is Moderate.

5.3 Draw and verify the pie chart

# Verify the severity counts and draw the pie chart
sum(severity_frequency)
round(100 * prop.table(severity_frequency), 1)

pie(severity_frequency,
    labels = paste(names(severity_frequency),
                   round(100 * prop.table(severity_frequency), 1), "%"),
    col = c("lightgreen", "gold", "tomato"),
    main = "Distribution of Confirmed-Case Levels")

Run the two verification lines separately. Then highlight the entire pie(...) command and run it.

  • Expected total: 270.
  • Expected percentages: approximately 65.6% Low, 27.8% Moderate, and 6.7% High.
  • The pie chart should appear in the Plots pane. No new object is created by pie().
Interpretation: Most state/date reports fall in the Low category under the stated thresholds. This describes reports, not unique patients, and the category names are analytical bins rather than clinical severity.
Checkpoint 4: Confirm the three counts total 270 and the pie chart has three labelled slices.

6. Task 3: Histogram of recovery numbers

The dataset calls the recovery column Cured. A histogram groups numerical recovery values into intervals and counts how many reports fall into each interval.

6.1 Inspect the values first

# TASK 3: Inspect recovery values before drawing the histogram
summary(covid$Cured)
table(covid$Cured, useNA = "ifany")

Run one line at a time.

  • Output expected: Yes.
  • New Environment object expected: No.
Expected check: minimum 0, maximum 9, and 215 of the 270 reports have Cured = 0. There are no missing values.
New argument explained

useNA = "ifany" tells table() to show missing values if any exist, guarding against the common mistake of overlooking missing data.

6.2 Draw the histogram

# Draw a histogram of recovery counts
hist(covid$Cured,
     breaks = seq(-0.5, 9.5, by = 1),
     col = "seagreen3",
     border = "white",
     main = "Distribution of Recovery Numbers",
     xlab = "Number cured in a report",
     ylab = "Frequency of reports")

Highlight the complete command and press Ctrl + Enter.

  • Output expected: Yes, a histogram in the Plots pane.
  • New Environment object expected: No.
Code explained
  • hist() draws a histogram.
  • seq(-0.5, 9.5, by = 1) creates evenly spaced boundaries so each whole-number recovery count has its own bin.
  • col controls the fill colour; border controls bar outlines.
  • xlab and ylab label the axes.
Interpretation: The distribution is strongly concentrated at zero. During this early period, most state/date reports recorded no cured cases. The histogram counts reports, so it must not be interpreted as 215 different groups of patients.
Checkpoint 5: The tallest bar should be at 0, and the x-axis should run through 9.

7. Task 4: Line chart of total cases over time

Each row is one place on one date. To plot the national trend, first convert the text dates into real R dates, then add total confirmed counts across all rows sharing a date.

7.1 Convert the date correctly

# TASK 4: Convert day-month-year text into R Date values
covid$DateConverted <- as.Date(covid$Date, format = "%d-%m-%Y")

Highlight the complete line and run it.

  • Printed output expected: No.
  • Environment change expected: Yes. covid should now have 10 variables.
Why the format matters: 30-01-2020 is day-month-year. Using a month-day-year instruction would fail for dates such as the 30th and could create missing values.

7.2 Verify the conversion

# Confirm that date conversion worked and created no missing dates
range(covid$DateConverted)
sum(is.na(covid$DateConverted))

Expected range: 2020-01-30 to 2020-03-21. Expected missing dates: 0. Output is expected; no new objects.

7.3 Create daily totals

# Add the total confirmed counts across all reports on each date
daily_total <- aggregate(TotalConfirmed ~ DateConverted,
                         data = covid,
                         FUN = sum)

Highlight the whole command and run it.

  • Printed output expected: No.
  • Environment object expected: Yes, daily_total with 52 observations and 2 variables.
Formula and symbols explained
  • aggregate() combines rows into groups.
  • TotalConfirmed ~ DateConverted means “calculate TotalConfirmed separately for each DateConverted.”
  • ~ separates the value being summarized from the grouping variable.
  • data = covid tells R where those columns are.
  • FUN = sum tells R to add the values in each date group.

7.4 Verify totals and draw the line chart

# Check the beginning and end of the daily series
head(daily_total)
tail(daily_total)

# Draw the daily total-confirmed trend
plot(daily_total$DateConverted,
     daily_total$TotalConfirmed,
     type = "o",
     pch = 16,
     col = "firebrick",
     main = "Trend of Total Confirmed Cases Over Time",
     xlab = "Date",
     ylab = "Total confirmed cases")

Run head() and tail() separately. Then highlight the entire plot(...) command and run it.

  • Expected final daily total: 283 on 2020-03-21.
  • Plot output expected: Yes.
  • New Environment object from plot: No.
Do not use sum(covid$TotalConfirmed) as the number of unique people across the entire file. The rows are repeated date-based reports and later reports include earlier ongoing cases. Summing all 270 rows gives 1,858 report-level case counts, which double-counts cases across dates.
Interpretation: The daily combined confirmed count rises slowly at first and then increases more rapidly in the second half of March, reaching 283 on 21 March 2020. This is a trend in cumulative state/date reporting, not a count of newly diagnosed cases per day.
Checkpoint 6: Confirm there are 52 dates, no missing converted dates, and the line ends at 283.

Symbols explained
  • == asks whether two values are equal. It performs a check.
  • = supplies a named instruction inside a function, such as data = covid.

11. Troubleshooting common beginner misses

Error: object 'covid' not found

The creation line was not run successfully. Return to Step 3.1, highlight the full covid <- read.csv(...) line, and press Ctrl + Enter. Confirm covid appears in the Environment before displaying or using it.

Cannot open file / no such file or directory

R is looking in the wrong folder, or the filename differs. Run list.files(). Compare the printed filename character by character. Set the working directory to the folder containing both the script and CSV.

Unexpected symbol or unexpected end of input

You may have highlighted only part of a multiline command or omitted a comma, quote, or parenthesis. Highlight from the function name through its final closing ) and run the whole command again.

The Console shows a plus sign instead of >

A + prompt means R thinks the command is unfinished, often because a closing quote or parenthesis is missing. Press Esc, return to the Script Editor, correct the command, highlight the entire command, and rerun it.

The code ran, but nothing was printed

If the line contains <-, no printed output is usually normal. Check the Environment for the object. To display it, run its name only after creating it.

object 'State.UnionTerritory' not found

Use names(covid) to inspect the exact imported names. The original slash normally becomes a period after read.csv(). Do not use spaces or a slash in the R column reference unless you deliberately use special quoting.

The date conversion produced NA values

Confirm the format is exactly "%d-%m-%Y". Here %d means day, %m means month, and %Y means four-digit year. Also confirm you imported the correct file.

The bar chart labels are crowded

Confirm horiz = TRUE, las = 1, and cex.names = 0.65. Make the Plots pane larger and rerun the whole barplot() command.

My totals differ from the guide

Stop rather than changing numbers manually. Check that you used the supplied 270-row file, did not filter rows, used row-wise addition for TotalConfirmed, and created daily_total by date. Restarting R and rerunning the clean script from top to bottom can expose an out-of-order step.
