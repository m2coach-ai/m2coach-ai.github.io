Three kinds of box appear throughout. Dark boxes are code you type into the Console (or into a script and run). Pale boxes are what R should print back. Amber boxes are traps: places where this particular dataset or R itself will quietly give you a wrong answer, or a confusing error, if you are not watching.

Two words you need before you start. Systolic blood pressure is the peak pressure in the arteries as the heart beats, and diastolic is the lowest pressure between beats. Both are measured in millimetres of mercury (mmHg) and written systolic over diastolic, such as 120/80. In this file they are the columns sbp and dbp. A correlation coefficient is one number between −1 and +1 that says whether the two variables rise together (positive), move in opposite directions (negative), or show no pattern (near zero). A scatter plot shows the same thing as a picture with one dot per person.

1Set up RStudio and the file

The only file you need is the SPSS data file. R cannot read the .sav format on its own, so you also need one add-on package, haven, which was written for exactly this.

  1. In RStudio choose File > New Project > New Directory > New Project. Name it something like health-bp and click Create Project. RStudio now treats that folder as home, so R can find files in it by name alone.
  2. In Windows File Explorer, copy the data file into the new project folder.
  3. Back in RStudio, look at the Files pane (bottom right). You should see the file listed. If you do not, click the small circular refresh arrow at the top right of that pane.
  4. Click in the Console (bottom left), type install.packages("haven") and press Enter. You do this once per computer. It needs an internet connection and takes under a minute.
  5. Choose File > New File > R Script. Save it straight away (Ctrl+S) as bp_correlation.R. Type each dark box below into this script and run the lines with Ctrl+Enter. Keeping everything in one script means you can rerun the whole analysis later with one click on Source.

Trap: the file name on the course page is not the name on your disk

The course link downloads Health Data.sav (with a space). The copy used for this guide is Health_Data.sav (with an underscore). Either is fine, but the name inside read_sav("...") must match the one in your Files pane exactly. The safest way is to type read_sav(", then press Tab inside the quotes: RStudio offers the files in your project folder, and you can pick the right one from the list.

Trap: keep install.packages() out of the script

Installing is a one-off job for the Console. If it sits in your script, it downloads the package again every time you run the script, and fails if you are offline. The line that belongs in the script is library(haven), which switches the installed package on for the current session.

A correlation is easy to calculate on data you have not looked at, and R will not warn you if something is wrong. Two minutes of checking first is cheap.

The first block is a five-number summary plus the mean for each column. Systolic runs from 91 to 195 mmHg with a mean of 127.7, and diastolic from 60 to 115 with a mean of 82.8. The second block counts missing values (NA). Both are zero, so every participant has both readings and nothing needs removing. Notice that the mean is a little above the median for both columns (127.7 against 123, and 82.8 against 82). That small pull upward hints at a tail of high readings. Section 7 checks whether the tail matters.

Two more checks, both about the structure of the data:

length(unique(health$sbp))
length(unique(health$dbp))
length(unique(health$ID_no))
sum(duplicated(health[, c("sbp", "dbp")]))
[1] 70
[1] 43
[1] 210
[1] 28
  • 70 and 43. There are only 70 different systolic values and 43 different diastolic values among 210 people, because blood pressure was recorded in whole mmHg. Many people therefore share exactly the same reading. These repeated values are called ties, and they matter twice later: R will warn about them in a Spearman test (Section 7), and they cause dots to sit on top of each other in the scatter plot (Section 5).
  • 210 different IDs. Each row is a different participant. That matters because correlation tests assume each observation is independent of the others, and one row per person makes that assumption far more reasonable than it would be for repeated daily measurements on the same people.
  • 28. Twenty-eight rows repeat a systolic and diastolic pair that has already appeared earlier in the file, so their dots will land exactly on an earlier dot.
Checkpoint: why look for missing values before calling cor()?

Because one missing value is enough to make cor() return NA for the whole calculation instead of a number. There are none in this file, so you will not hit it, but the trap in Section 4 shows what it looks like and how to fix it.

4Task 1: the correlation

One line does it. health$sbp means "the sbp column of health", so the line below correlates the two columns.

cor(health$sbp, health$dbp)
[1] 0.846808

By default cor() calculates Pearson's r, which measures how closely the dots follow a straight line. Read it in three parts:

  • Sign. Positive, so people with higher systolic pressure tend to have higher diastolic pressure.
  • Size. 0.85 is close to +1, so the relationship is strong. Textbooks draw the lines between "moderate", "strong" and "very strong" in slightly different places, so describe it in words and give the number rather than relying on a label alone.

Squaring r tells you the proportion of the variation in one variable that goes along with the other:

round(cor(health$sbp, health$dbp)^2, 3)
[1] 0.717

About 72% of the spread in diastolic pressure lines up with systolic pressure. The other 28% is everything else: the person, the time of day, the cuff, the arm, the measurement itself.

Checkpoint: does it matter which variable goes first in cor()?

Not for the number. Swapping them gives the identical result:

cor(health$dbp, health$sbp)
[1] 0.846808

It does matter later, for the scatter plot (which variable goes on the horizontal axis) and for the fitted line in Section 6. For a correlation alone, the order is arbitrary.

Trap: handing cor() the whole data frame

It is tempting to write cor(health) and let R correlate everything. The file contains text columns (sex is stored as the letters f and m), and cor() only works on numbers:

cor(health)
Error in cor(health) : 'x' must be numeric

Always name the two columns you want, as in cor(health$sbp, health$dbp), or pick a block of numeric columns, as in cor(health[, c("sbp", "dbp")]).

Trap: one missing value turns the answer into NA

This file is complete, so to see the problem you have to cause it. The code below copies systolic into a spare object x, blanks out its third value, and tries again. Your health data is not changed.

x <- health$sbp
x[3] <- NA
cor(x, health$dbp)
cor(x, health$dbp, use = "complete.obs")
[1] NA
[1] 0.8476069

The first call returns NA. Adding use = "complete.obs" tells R to drop any row with a missing value and calculate from the rest. If you ever see NA from cor() on real data, this is the first thing to try. Do not use it without checking how many rows were dropped.

Is the correlation distinguishable from zero? cor.test()

A correlation from 210 people is an estimate. A different 210 people would give a slightly different r. cor.test() reports how uncertain the estimate is.

cor.test(health$sbp, health$dbp)
	Pearson's product-moment correlation

data:  health$sbp and health$dbp
t = 22.961, df = 208, p-value < 2.2e-16
alternative hypothesis: true correlation is not equal to 0
95 percent confidence interval:
 0.8035436 0.8811723
sample estimates:
     cor 
0.846808
  • t = 22.961, df = 208 is the test statistic and its degrees of freedom. The degrees of freedom are n − 2, so 210 − 2 = 208.
  • p-value < 2.2e-16 is the probability of a correlation at least this strong if the true correlation were zero. It is vanishingly small.
  • 95 percent confidence interval gives 0.804 to 0.881: plausible values for the true correlation in the wider group these participants came from.
  • alternative hypothesis says the test is two-sided. It checks for a correlation in either direction.

Trap: p-value < 2.2e-16 does not mean p is zero

R prints this form once a p-value falls below its numerical precision (about 2.2e-16, which is 0.00000000000000022). Report it as p < .001. Never write p = 0.

With 210 people, even a modest correlation would produce a tiny p-value, so the p-value is the least informative part of this output. The two numbers worth reporting are r (how strong) and the interval (how precisely it is known). Section 7 returns to this.

5Task 2: the scatter plot

Build the plot in layers so you can see what each piece adds. Run each step and look at the Plots pane (bottom right).

Step 1: the one-line version

plot(health$sbp, health$dbp)

The first column you name goes on the horizontal (x) axis and the second on the vertical (y) axis.

Step 2: labels, a title and see-through dots

Extra arguments go inside the brackets, separated by commas. Put each on its own line so the code stays readable.

plot(health$sbp, health$dbp,
     xlab = "Systolic BP (mmHg)",
     ylab = "Diastolic BP (mmHg)",
     main = "Systolic vs diastolic blood pressure (n = 210)",
     pch  = 19,
     col  = rgb(36, 101, 95, alpha = 128, maxColorValue = 255))
  • xlab and ylab name the axes, and main is the title. Always put units on the axis labels.
  • pch = 19 picks solid round dots.
  • col = rgb(36, 101, 95, alpha = 128, maxColorValue = 255) builds a colour from red, green and blue amounts (each 0 to 255), and alpha sets the opacity. 128 is about half see-through, so where dots overlap the colour builds up and darkens. That matters here because 28 rows repeat a pair that already appeared (Section 3).

Step 3: add the line of best fit

Run the whole block again with one extra line at the end. abline() draws a straight line on top of whatever plot is currently open, and lm(dbp ~ sbp, data = health) works out the line that sits closest to all the dots. Read the formula dbp ~ sbp as "diastolic explained by systolic". The colour "#8A4500" is a hex colour code for a dark amber, which stands out against teal.

plot(health$sbp, health$dbp,
     xlab = "Systolic BP (mmHg)",
     ylab = "Diastolic BP (mmHg)",
     main = "Systolic vs diastolic blood pressure (n = 210)",
     pch  = 19,
     col  = rgb(36, 101, 95, alpha = 128, maxColorValue = 255))
abline(lm(dbp ~ sbp, data = health), col = "#8A4500", lwd = 2)

Trap: abline() needs a plot to draw on

Run the abline() line on its own in a fresh session and you get:

abline(lm(dbp ~ sbp, data = health), col = "#8A4500", lwd = 2)
Error in int_abline(a = a, b = b, h = h, v = v, untf = untf, ...) : plot.new has not been called yet

The message is accurate but unhelpful. It means no plot exists yet, so plot() has to run first. The quieter version of this mistake is worse: if an older plot is still showing in the Plots pane, abline() draws the line on that old plot without any warning. Select the plot() lines and the abline() line together and run them in one go with Ctrl+Enter.

Checkpoint: which variable goes on which axis?

For the correlation it makes no difference: swapping the axes flips the picture but leaves r unchanged. For the fitted line it does matter, because the line for "diastolic explained by systolic" is not the same line as "systolic explained by diastolic". Putting systolic on the horizontal axis is the usual convention here. Whichever you choose, say which one in your write-up.

Optional: separate the stacked dots with jitter

Jitter nudges every dot by a tiny random amount so that dots sharing an identical reading pair no longer sit exactly on top of each other. set.seed(42) makes the random nudging repeatable, so you and a classmate get the same picture. This is optional polish, and it changes the drawing only. The correlation is always calculated from the original values.

set.seed(42)
plot(jitter(health$sbp, amount = 0.5), jitter(health$dbp, amount = 0.5),
     xlab = "Systolic BP (mmHg)",
     ylab = "Diastolic BP (mmHg)",
     main = "Same data with jitter",
     pch  = 19,
     col  = rgb(36, 101, 95, alpha = 128, maxColorValue = 255))
abline(lm(dbp ~ sbp, data = health), col = "#8A4500", lwd = 2)

6Reading the plot and the number together

Describe four things every time: direction, form, strength, and anything unusual. The plot and r check each other. The number alone can hide a curve or a few extreme points, and the plot alone cannot say how strong the pattern is.

The amber line in the plot has a formula, and R will give it to you:

fit <- lm(dbp ~ sbp, data = health)
round(coef(fit), 3)
round(summary(fit)$sigma, 1)
(Intercept)         sbp 
     19.407       0.496 
[1] 6.3

Reading Task 2

  • Direction: upward. Dots rise from left to right, matching the positive r.
  • Form: roughly straight. The cloud follows the line across the whole range, with no obvious curve.
  • Strength: strong, with real scatter. The fitted line is diastolic = 19.407 + 0.496 × systolic. The slope says that a participant with a systolic reading 10 mmHg higher has, on average, a diastolic reading about 5 mmHg higher. The 6.3 is roughly the typical distance of a dot from the line, in mmHg. So the line is a good summary of the average pattern, but it would be off by around 6 mmHg for a typical individual.
  • Unusual points: a few on the far right. Three participants have systolic readings of 186, 190 and 195, well beyond everyone else. They sit below the fitted line rather than along it, which is one reason to test how much influence they have. Section 7 does that.

The intercept (19.407) is not meaningful on its own, because nobody has a systolic reading of zero. It is simply where the line has to start to fit the cloud.

A careful sentence for your portfolio: "In these 210 participants, higher systolic blood pressure was associated with higher diastolic blood pressure, with a strong, roughly linear relationship." Notice that it describes an association in a sample, not a cause.

7Is r = 0.85 the whole story? Read this before you answer

The brief asks only for the correlation and the plot. But a single number can mislead, and the Unit 8 material on nonparametric tests gives you the tools to check it. Run the checks below, then decide how to report.

Check 1: Pearson's r assumes roughly normal data. Is that true here?

shapiro.test(health$sbp)
shapiro.test(health$dbp)
	Shapiro-Wilk normality test

data:  health$sbp
W = 0.95474, p-value = 3.345e-06


	Shapiro-Wilk normality test

data:  health$dbp
W = 0.97052, p-value = 0.0002204

The null hypothesis of a Shapiro-Wilk test is that the data are normally distributed. Both p-values are below .001, so there is clear evidence that neither variable is perfectly normal. With 210 people this test picks up even small departures, so treat it as a prompt to check, not a verdict. The safe response is to run a method that does not assume normality and see whether the answer changes. Spearman's rho converts each value to a rank (smallest = 1, next = 2, and so on) and correlates the ranks, so it only cares whether higher goes with higher.

cor(health$sbp, health$dbp, method = "spearman")
cor.test(health$sbp, health$dbp, method = "spearman")
[1] 0.8018198

	Spearman's rank correlation rho

data:  health$sbp and health$dbp
S = 305884, p-value < 2.2e-16
alternative hypothesis: true rho is not equal to 0
sample estimates:
      rho 
0.8018198 

Warning message:
In cor.test.default(health$sbp, health$dbp, method = "spearman") :
  Cannot compute exact p-value with ties

Spearman's rho is 0.802, a little lower than Pearson's 0.847, and still strong. The conclusion does not depend on which method you pick. Report Pearson as the main figure (the plot is roughly straight and the sample is large) and Spearman as a check, and say that the two agree.

Trap: "Cannot compute exact p-value with ties" is a warning, not an error

Blood pressure was recorded in whole mmHg, so many participants share a reading (Section 3 showed only 70 different systolic values among 210 people). Tied values cannot be ranked uniquely, so R falls back on an approximation for the p-value. With 210 participants the approximation is fine. Nothing needs fixing, but mention it in your write-up so a reader knows you noticed.

Check 2: are a few extreme points driving the result?

Rather than picking outliers by eye, use a rule. The boxplot rule flags any value more than 1.5 times the interquartile range (IQR) above the third quartile or below the first. First the quartiles for systolic:

quantile(health$sbp, c(0.25, 0.75))
   25%    75% 
114.00 141.75

The IQR is 141.75 − 114 = 27.75, so the upper fence is 141.75 + 1.5 × 27.75 = 183.4. Anything above that is flagged. The same rule is applied to diastolic in the code below, then r is recalculated without every flagged row.

out_sbp <- boxplot.stats(health$sbp)$out
out_dbp <- boxplot.stats(health$dbp)$out
out_sbp
out_dbp
keep <- !(health$sbp %in% out_sbp | health$dbp %in% out_dbp)
sum(keep)
cor(health$sbp[keep], health$dbp[keep])
[1] 186 190 195
[1] 115 115
[1] 205
[1] 0.8390281

The rule flags three systolic readings (186, 190, 195) and two diastolic readings (both 115). The line keep <- ... builds a yes/no marker for each row, where %in% means "is one of", | means "or", and ! flips the answer, so keep is true for rows with neither kind of extreme value. That leaves 205 participants, and r is 0.839 against 0.847 for everyone. The result is stable. It describes the whole sample, not five unusual people.

Check 3: a wide range props up a correlation

Correlations get stronger when the data cover a wide range, because the overall trend dominates the noise. This sample includes many people with normal readings and a group with high readings. Split at 140 mmHg, the conventional clinic threshold for raised systolic pressure, and correlate within each half:

low <- health$sbp < 140
sum(low)
round(cor(health$sbp[low],  health$dbp[low]), 3)
round(cor(health$sbp[!low], health$dbp[!low]), 3)
[1] 146
[1] 0.555
[1] 0.637

Among the 146 participants below 140, r is only 0.555, and among the 64 at or above 140 it is 0.637. Both are clearly positive, and both are well below the overall 0.847. Part of the headline figure comes from the sample spanning normal and high readings, not only from how closely the two pressures track each other within a range. So the honest statement is that the overall correlation is strong, and that it is moderately strong within narrower bands. The cut at 140 is also a choice. Try 130 and see how the numbers shift, then report the cut point you used.

Check 4: is age hiding behind both variables?

Blood pressure usually rises with age, so age could push both readings up and create a correlation between them on its own. This is the same idea as time being a confounder in the COVID cross-tab activity. Check it directly:

cor(health[, c("age", "sbp", "dbp")])
            age         sbp         dbp
age  1.00000000 -0.03783961 -0.02244252
sbp -0.03783961  1.00000000  0.84680799
dbp -0.02244252  0.84680799  1.00000000

Read the top row: age correlates with systolic at −0.038 and with diastolic at −0.022, which is essentially nothing in this sample. To be thorough, strip age out of both variables and correlate what is left. resid() returns what remains of each reading after removing the part that age explains:

sbp_adj <- resid(lm(sbp ~ age, data = health))
dbp_adj <- resid(lm(dbp ~ age, data = health))
cor(sbp_adj, dbp_adj)
[1] 0.8467783

The correlation after adjusting for age is 0.847, the same as before. So age is not the link between the two pressures here. This is a check that came back clean, and saying so in your write-up is worth a sentence, because it shows you looked for a confounder and did not find one.

Check 5 (optional): does the correlation differ between groups?

In the dataset, diabetes is coded 1 for yes and 2 for no. Correlate within each group, and add a confidence interval to each so you can judge the difference:

dm <- health$diabetes == 1
c(with_diabetes = sum(dm), without = sum(!dm))
round(cor(health$sbp[dm],  health$dbp[dm]), 3)
round(cor(health$sbp[!dm], health$dbp[!dm]), 3)
round(cor.test(health$sbp[dm],  health$dbp[dm])$conf.int[1:2], 2)
round(cor.test(health$sbp[!dm], health$dbp[!dm])$conf.int[1:2], 2)
with_diabetes       without 
           45           165 
[1] 0.72
[1] 0.87
[1] 0.54 0.84
[1] 0.83 0.90

Participants with diabetes show r = 0.72 (n = 45) against 0.87 (n = 165) for those without. That looks like a difference, but the two intervals (0.54 to 0.84 and 0.83 to 0.90) overlap, and the smaller group gives a much wider interval. Treat this as something worth a second look, not as a finding. Comparing the two correlations properly would need a test designed for that, which this activity does not ask for.

What to report instead of "p < .001"

The p-value says the correlation is unlikely to be exactly zero, which was never in doubt. A reader learns far more from the size of r and the width of its interval:

round(cor.test(health$sbp, health$dbp)$conf.int[1:2], 3)
[1] 0.804 0.881

Report r = 0.85 with a 95% confidence interval of 0.80 to 0.88, Spearman's rho as a robustness check, and the checks above in a line or two. One caveat about the interval: Greenland et al. (2016) stress that a p-value or confidence interval is calculated from a whole statistical model, including its assumptions about how the data were collected, not just from the numbers. Here the rows are separate participants, which helps. But the file does not say how participants were chosen, so the interval describes sampling uncertainty only if they behave like a random sample of some wider group. Say that in your write-up.

Checkpoint: what is wrong with "p < .001, so higher systolic pressure causes higher diastolic pressure"?

Three things. A p-value does not measure how strong or important a relationship is (r and its confidence interval do that). It is calculated assuming the model is correct, which depends on how the participants were selected. And a correlation in observational data says nothing about cause: both readings come from the same heartbeat in the same arteries, so it would be surprising if they did not move together. The correlation describes a pattern across these 210 participants, not what would happen inside any one person.
