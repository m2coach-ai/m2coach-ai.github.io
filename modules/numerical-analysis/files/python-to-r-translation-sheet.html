Reference sheet

Python → R

For someone fluent in Python, NumPy and pandas who is new to R. This is a diff, not a tutorial. It assumes you already know what a vector, a data frame and a group-by are, and only covers where R disagrees with what you would expect.

⚠ marks rows where the same syntax is legal in both languages and means different things. Those are the ones that cost hours, because nothing errors.

01 The six that will actually bite you

Everything else on this sheet you can look up. These you have to internalise, because Python habits produce silently wrong answers rather than exceptions.

Negative indexing is exclusion

In Python x[-1] is the last element. In R it is everything except the first. Both return a value, neither errors.

# Python
x[-1]      # last element
# R
x[-1]      # all but the first
x[length(x)]   # the actual last
tail(x, 1)     # clearer

1-indexed, and ranges include the end

1:3 is three elements, not two. x[1] is the first. Every off-by-one instinct you have is calibrated wrong.

# Python: 3 elements, 0 1 2
range(3)
# R: 3 elements, 1 2 3
1:3

1:n when n is 0

The single most common R loop bug. 1:0 counts down and yields c(1, 0), so an empty-collection loop runs twice. Python's range(0) is simply empty.

n <- 0
1:n            # 1 0  (runs twice!)
seq_len(n)     # integer(0)  correct
seq_along(x)   # use for indices

Recycling is not broadcasting

NumPy refuses incompatible shapes. R repeats the shorter vector and only warns if the longer length is not a clean multiple. Compatible-but-wrong runs silently.

c(1,2,3,4) + c(10,20)
# 11 22 13 24, no warning
c(1,2,3) + c(10,20)
# 11 22 13, with a warning

Strings are atomic, not sequences

You cannot index into a string. "hello"[1] returns the whole string, because R sees a length-1 character vector and you asked for its first element.

"hello"[1]           # "hello"
substr("hello",1,1)  # "h"
nchar("hello")       # 5, not length()
length("hello")      # 1

Out-of-bounds does not raise

Reading past the end gives NA. Writing past the end silently grows the vector and pads with NA. Python raises IndexError for both.

x <- c(1,2,3)
x[10]        # NA
x[6] <- 99   # length is now 6
x            # 1 2 3 NA NA 99

09 Things with no Python equivalent

Four R concepts that will not map onto anything you already know, so learn them as new rather than as translations.

ConceptWhat it is and why it matters
factorA categorical vector stored as integer codes plus a lookup table of levels. Level order controls the reference group in models and the category order on plots, and defaults to alphabetical. as.numeric() on a factor returns the internal codes, not the labels: use as.numeric(as.character(f)). Closest analogue is pandas.Categorical, but factors are far more central in R.
formula, y ~ xA first-class object capturing "response explained by predictors". It is the shared interface across t.test, aggregate, boxplot, lm, glm and most modelling packages. Learning it once unlocks all of them.
attributesArbitrary metadata attached to any object. dim, names, class and levels are all just attributes, which is why setting dim() on a vector turns it into a matrix in place.
generic dispatchsummary(), print() and plot() change behaviour based on the class of their argument. summary() on a vector, a data frame and a fitted model return three different things. This is why the same handful of function names does so much work.

10 A first session, translated

The same small analysis written both ways.

# Python
import pandas as pd

df = pd.read_csv("data/trees.csv")
df.info()
print(df.height.isna().sum())

df["ratio"] = df.height / df.dbh
oaks = df[df.species == "oak"]
print(oaks.height.mean())
print(len(oaks))

df.groupby("species")["height"].agg(["count", "mean", "std"])
# R
trees <- read.csv("data/trees.csv")
str(trees)
sum(is.na(trees$height))

trees$ratio <- trees$height / trees$dbh
oaks <- trees[trees$species == "oak", ]     # note the comma
mean(oaks$height, na.rm = TRUE)             # note na.rm
nrow(oaks)

aggregate(height ~ species, trees, function(v)
  c(n = length(v), mean = mean(v), sd = sd(v)))

Two differences carry most of the weight. The comma in trees[trees$species == "oak", ] is the difference between selecting rows and selecting columns, and R will not tell you which one you asked for. And na.rm = TRUE is not optional noise: pandas skips missing values by default when computing a mean, R propagates them, so the same code returns a number in Python and NA in R. Neither behaviour is wrong, but assuming pandas' default in R gets you NA, and assuming R's default in pandas gets you a mean over an unknown subset.
